## The missing allelic output — what it was

`11F202618760`'s copy-number tab had no allelic state and no window plots.
Not a pipeline failure: the four genebaf files were written to the tree at
06:11 and the report was generated at 06:07. The bundle guard
(`bundle_guard_v1`) polls only for the artefact kinds it is given, and
genebaf was not one of them, so it reported the tree complete and the bundle
was built four minutes early.

`build_report_bundle.sh` already collected all four files — it was given
nothing to collect. The fix is entirely in the guard.

The same exposure existed one column over: the workflow required `cnv`
(ichorCNA's own `params.txt`), which is two processes upstream of what the
dashboard actually reads — the ichorkaryo JSON and the ICHORCNA_PLOT
figures. Both are now required kinds, gated as `hg38_track.nf` gates their
producers.

## hg38 gene model (open item 4, closed)

RefSeq GRCh38.p14 GFF downloaded to
`/goast/hemat_data/references/refseq_grch38/GCF_000001405.40_GRCh38.p14_genomic.gff.gz`.

`build_mm_gene_model.py` derives contig naming by pairing a chr-named and an
NC_-named panel BED; the hg38 panel ships only the chr-named file, so
`bin/bed_chr_to_nc.py` writes the NC_ twin, taking the accession mapping
from the GFF's own `region` records rather than a typed table.

The hg38 panel has 66 windows to T2T's 68 — IGH and IGK are absent, which is
consistent with the hg38 track being SNV/CNV only. The gene model is
annotation, not capture, so both were added back with `--extra-genes
IGH,IGK`; the symbol set now matches the T2T model exactly (73 features).
IGH lands at chr14:105.59–106.88 Mb, IGK at chr2:88.86–90.24 Mb.

## Findings worth remembering

- **A guard only watches what it is told to watch.** Third publish race in
  three days, and the first two fixes did not prevent it. Any artefact the
  dashboard reads needs to be a required kind; `cn` and `cnfig` were added
  today for the same reason. If a new published output becomes a report
  input, it belongs in `check_published_outputs.sh` and in the workflow's
  `required_kinds` in the same commit.
- **A dead checkbox looks exactly like a live one.** The Include boxes on
  the genome and per-chromosome figure cards had done nothing since
  `dashboard_mm_v3` renamed the pane from `#tab-cnv` to `#tab-copy-number`
  yesterday: `initCNVGallery()` looked the old id up, got null and returned.
  Nothing in the page said so. The lookup now falls back to the document.
- **Inline tab scripts run before `variant-browser.js`.** It is loaded at
  the end of `<body>`, so any tab script that needs the reporting store must
  wait for `window load` — the first version of the rearrangement Include
  wiring did not, and the boxes ticked with no listener behind them. Both
  wirings now wait.
- **`bin/` scripts do affect the task hash.** All 14 ICHORCNA_PLOT tasks
  re-executed after `mmplot.py` changed, contrary to what I assumed when
  reading the first 1m 19s run. A figure change does not need forcing.
- **`supp_vec` is not the support record.** On `11F202618760`'s t(4;14) the
  vector reads `1011` while `support_cutesv` is 13. The vector is SURVIVOR's
  presence record at merge time; the per-caller support fields are
  re-derived afterwards from each caller's own VCF. The detail key says to
  trust the support fields.

## Conventions confirmed today

  in a command line (`-profile <same profile>`) get executed literally — give
  the real command or none.
