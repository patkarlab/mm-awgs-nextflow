# Changes — 2026-07-21

Annotation-layer corrections to the hg38 SNV track and the T2T translocation
track, plus a reporting-bundle utility. Each fix was applied via an idempotent
patch script (retained under `bin/patches_applied/`) that writes a `.bak` and
refuses double-application.

No clinical findings, sample identifiers, variants, or per-sample results are
recorded here or anywhere in this repository. Gene symbols and gene regions are
the only genomic identifiers committed.

---

## 1. SNV filter reads panel membership from the BED (was hardcoded)

**Symptom.** `filter_v6_somatic_candidates.py` carried a hardcoded v6 gene
dictionary, so genes present in a newer panel but absent from that list were
silently dropped from the clinical output.

**Root cause.** Panel membership was baked into the script rather than derived
from the active panel BED, allowing the filter and the panel to drift apart.

**Fix.** The filter now loads its gene set at runtime from the hg38 panel BED
(column 4) via a required `--panel-bed` argument. Membership is tested by token
set, with a small alias map for legacy symbol differences (FAM46C to TENT5C,
WHSC1/MMSET to NSD2, NIK to MAP3K14, HIST1H1E/H1F4 to H1-4). Compound BED labels
are normalised (`/`, `+` to `_`). The calling module
(`modules/local/filter_v6_report.nf`) passes `--panel-bed ${params.panel_bed_hg38}`.

---

## 2. Off-panel translocation partners characterised by cytoband

**Symptom.** Translocation partners outside the panel were reported as
`OFF_PANEL` / `unknown`.

**Root cause.** The annotator resolved partner identity only against panel
regions, with no fallback for off-panel breakpoints.

**Fix.** Added a cytoband table loader and a `characterize_side()` step
returning `(label, source)` with `source` in `{panel, cytoband, coordinate}`.
Off-panel breakpoints resolve to their cytoband. New columns `gene_a_source` /
`gene_b_source` record provenance and flow through `merge_translocations.py`.
The cytoband BED (`assets/chm13v2.0_cytobands_allchrs.bed`, T2T) is passed via
`--cytoband-bed ${params.cytoband_bed_t2t}`. The known-pair dictionary lookup is
guarded to fire only when both sides are panel genes.

## 3. `merge_translocations.py` `_ends` tuple unpack fix

**Symptom.** After the cytoband change extended the `_ends` records from
3-tuples to 4-tuples (adding `source`), one unpack site in `ig_aware_union`
still expected three values.

**Root cause.** A single positional unpack was missed when the tuple width
changed.

**Fix.** Updated the unpack to accept the fourth (`source`) element.

---

## 4. `known_mm_pair` / `known_freq` matching (were unpopulated)

**Symptom.** The known-partner columns were empty for every translocation,
including canonical Ig events that should match the curated dictionary.

**Root cause.** A naming-convention mismatch. The translocation dictionary
names Ig partners with a `_locus` suffix (`IGH_locus`) and joins compound
partners with `_` (`FGFR3_NSD2`, `WWOX_MAF`), while the panel BED labels the
same regions plainly (`IGH`) and with `/` (`FGFR3/NSD2`, `WWOX/MAF`). The lookup
compared these as exact strings, so no canonical pair matched.

**Fix.** Matching now works on gene identity, not exact label. Each partner name
is reduced to a set of gene tokens (split on `/` and `_`, uppercased,
region-suffix words like `LOCUS` dropped), and two partners match when their
token sets intersect, which also handles a BED region carrying an extra
component the dictionary does not name (e.g. an `IGL/IGLL5` label matching an
`IGL_locus` dictionary entry on the shared `IGL` token). The dictionary is
loaded as a list of token-set entries and scanned by intersection. A sidecar
`assets/mm_translocation_dictionary.README` documents the convention.

## 5. HGVS c./p. annotation restored (VEP `--hgvs` re-enabled)

**Symptom.** SNV output carried consequence and rsID but no HGVS coding (`c.`)
or protein (`p.`) notation.

**Root cause.** `--hgvs` had been removed from the VEP call as a workaround for
a multi-allelic crash in VEP v113. The underlying cause is that VEP HGVS
calculation fails on multi-allelic records; the flag was dropped rather than the
records being split.

**Fix.** Split multi-allelic sites to biallelic with `bcftools norm -m-` before
VEP, then re-enable `--hgvs`. The `bcftools +split-vep` format string gains
`%HGVSc` / `%HGVSp`, the reshape step carries the two new fields, both TSV
header definitions gain `hgvsc` / `hgvsp`, and the filter's preferred columns
include them. Columns are appended at the end of the layout so no existing
column index shifts. HGVSp is kept in VEP's native three-letter form.

Note: synonymous changes render with URL-encoded `%3D`; these are
protein-non-altering and are removed by the consequence filter.

## Reporting utility

`bin/build_report_bundle.sh` assembles a per-sample view of an existing results
directory (SNV, translocation, and CNV outputs into
`<sample>/{snv,translocations,cnv}/`) by copying real files and tarring the
result. It reads from a results directory, does not modify pipeline output, and
produces no tracked artefacts.
